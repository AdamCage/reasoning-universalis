# Post-data Windows ledger I/O finding

Windows CI run [42493249898](https://github.com/AdamCage/reasoning-universalis/actions/runs/42493249898), job 128769954479, failed during synthetic R1 evidence-fixture generation with WinError 5 / AccessDenied at the frozen Stage-0 Ledger.flush() atomic replacement of ledger.tmp over ledger.json. Linux unit tests and actual sealed A→R1 byte-exact archive replay passed. This Windows failure is an engineering finding; it is not relabelled as a scientific outcome.

The frozen R1 _check_sources() path calls _verify_original_a(), which reads the retained ledger without acquiring the shared budget lock. A concurrent worker may finalize a response and atomically replace the same file. Windows can refuse replacement while a reader holds a file handle without delete sharing. The writer lock alone does not coordinate that reader. Antivirus/indexing interference can also cause Windows sharing errors, so the traceback alone does not identify a unique OS-level cause. A deterministic native sharing-handle test demonstrates the relevant failure mechanism.

The measured A13/R1 collector 07e83c0892ce77a6d1b59a755a91f6bf57b70c4b7d783df40d5377eb6074a440, sources, raw calls, ledgers, labels and sealed archives remain unchanged. The actual continuation retained 194 known finalized calls, with no observed occurrence of this failure in collection. Successful actual collection does not establish race freedom.

The archive/replay test now creates its synthetic raw journal with a serial scheduler. That test verifies portable evidence and replay, rather than concurrent collector I/O. Separate compatibility tests retain and exercise the discovered concurrency issue; serial fixture construction is not presented as a fix to the measured collector.

The two ordinary synthetic runner/recovery factories use the compatibility mixin while retaining the original three-worker executor, so budget, unknown-cache, provider and concurrency business rules are still exercised concurrently. Their synthetic protocol flag explicitly permits this post-data test adapter. The compatibility comparison deliberately constructs the original measured class directly, bypassing those factories, to preserve an actual frozen baseline.

scripts/pilot_v2_ledger_io_compat_v1.py is a new post-data cooperative adapter. It wraps retained/check-ledger reads in the same thread and OS budget lock as writers, and tracks owner-thread reentry to avoid taking a second Windows byte lock during nested inherited calls. It does not change request bodies, grading, eligibility, costs, reservations, source snapshots or retry policy. Tests compare completed and truncated records and their raw bytes, retain unknown reserves without resend, exercise nested lock cleanup and block an atomic writer until the coordinated reader closes its handle.

This helper was not used to collect or replay the measured evidence. Its paid entry point refuses the existing live protocols. A future production revision must prospectively bind the helper version/path/SHA in a new protocol and include the file in its frozen source inventory, with a separately authorized bounded execution condition. All processes sharing the ledger must participate in cooperative locking. External readers and unmodified concurrent collectors remain outside this lock contract. No new model requests are made by this correction.
