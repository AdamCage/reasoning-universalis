# Протокол разметки v0.1

**Отложенная человеческая валидация.** Пользователь выбрал сейчас только ансамбль DeepSeek, без человеческого эталона. Действующая подготовка разметки — [MACHINE_ANNOTATION_PROTOCOL.md](MACHINE_ANNOTATION_PROTOCOL.md). Настоящий документ сохранён для будущей независимой валидации и не описывает уже выполненную разметку. E0 не пройден.

Статус: development-дизайн, не G1/G2. Объект — функциональная роль **наблюдаемого текста**. Внутренний процесс модели по этой разметке не восстанавливается. Отдельные LLM-разметчики не используются.

## Единица, контекст и слепая разметка

Основная единица — сегмент с неизменным `segment_id`, SHA-256 трассы и границами Unicode code points `[start,end)`. Текст не нормализуется; CRLF входит в координаты. Для роли аннотатор получает условие задачи без gold answer, текущий сегмент и два предшествующих сегмента (не более 1000 символов). Модель, provider, correctness, split и автоматическая метка скрываются. Если этого недостаточно, запросить полную видимую трассу и отметить `context_extended=true`; такие случаи анализировать отдельно. Отдельный финальный ответ API не показывается. Ответ, уже присутствующий внутри reasoning, не вырезается: это изменило бы объект измерения.

Границы S1 аннотируются отдельно **до** автоматических кластеров/ролей: разрыв отмечает смену выполняемой операции или стратегии. Не делить формулу, код или одно вычисление ради совпадения со словарём. Аннотаторы независимо задают границы по полной трассе; фиксируют сомнительные границы. S2/S3 получают собственную разметку: нельзя механически переносить одну роль между разными сегментациями.

## Словарь

| Код | Определение | Положительный пример | Отрицательный/пограничный пример |
|---|---|---|---|
| `problem_formulation` | Переформулировка цели, данных или ограничений, без нового вывода | «Нужно найти целое x с двумя остатками» | «Из остатков следует x=31» — deduction |
| `planning` | Выбор способа дальнейшего решения без выполнения | «Сначала перечислим случаи, затем проверим ограничения» | Уже перечисленные и оценённые случаи — exploration |
| `deduction_computation` | Получение нового вывода/значения из данных | «Подставляя x=3, получаем y=7» | Подстановка для проверки уже найденного y — verification |
| `exploration` | Рассмотрение альтернативных путей/кандидатов без принятого единственного пути | «Можно перебрать случаи или применить инвариант» | Заявление выбранной стратегии — planning |
| `verification` | Проверка существующего результата по независимому условию, примеру или повторному вычислению | «Проверим 31: остатки равны 3 и 1» | Первое вычисление остатка как нового шага — deduction |
| `uncertainty` | Содержательная оценка недостающих данных/сомнения | «Этого условия недостаточно, остаются два допустимых случая» | «Вероятно, 2+2=4» без анализа сомнения — deduction |
| `backtracking_correction` | Отмена, пересмотр или исправление предыдущего шага с явной связью | «Предыдущий знак неверен; заменим минус на плюс» | «Wait» без исправления — не достаточный признак |
| `conclusion` | Явное предъявление ответа поставленной задаче | «Итак, ответ задачи: 31» | Промежуточное «значит y=7» — deduction |
| `ambiguous_other` | Неясная роль, неразделимый смешанный сегмент, форматирование или текст вне словаря | Два равноправных действия в неразделимом фрагменте | Не выбирать этот код только из-за сложности математики |

Аннотатор записывает `primary_role`, `secondary_roles`, `confidence` (high/medium/low), `reason_code`, текстовое пояснение и `context_extended`. Если сегмент можно переопределить только сменой границ, не менять их в задании разметки роли: отметить `boundary_problem`. При двух самостоятельных действиях без доминирующего основная метка ambiguous, вторичные сохраняются. Для исправления, включающего пересчёт ошибочного шага, primary — correction, secondary — deduction. Для содержательной проверки с вычислением primary — verification. Триггерные слова сами по себе метку не определяют.

Conclusion внутри reasoning может быть пересмотрено позже; это не поглощающее состояние. Завершение API — отдельное событие END, не девятая функциональная роль. Ambiguous не удаляется молча и не склеивает соседние переходы: динамические оценки должны показывать долю пропусков и чувствительность.

## Независимость и разрешение разногласий

Предварительная E0-выборка размечается двумя людьми целиком. Они проходят тренировку на отдельном development-наборе, обсуждают правила, затем независимо размечают оценочный набор. До сдачи второй разметки нельзя видеть первую. На основном корпусе доля двойной разметки будет определена G2; здесь численного окончательного решения нет.

Сначала сохранить обе независимые версии; Cohen kappa, raw agreement и соглашение по каждому классу вычислять **до** adjudication. Затем третий человек или назначенный человек-арбитр разбирает расхождения с пояснениями; фиксировать его имя, решение и версию протокола. Если третий недоступен, согласованное обсуждение двух людей записать явно, не называть независимой третьей оценкой. Gold — результат adjudication, исходные оценки сохраняются. Не создавать фиктивные имена, голоса или G1/G3.

Все задания выбираются по task roots, семействам и доменам до просмотра correctness; отдельно отмечаются страты редких ролей для coverage и естественная случайная выборка для частот. Oversampling редких классов не используется без весов для оценки их распространённости. Перефразы одного root не являются независимыми наблюдениями.

После просмотра measurement-validation изменения онтологии, инструкций или сегментации создают новую revision и требуют новой закрытой валидации. Журнал: дата, автор, причина, изменённые классы/границы, hashes старой и новой версии, виденные roots. Confirmatory-корпус не используется для таких решений.
