# Варианты решений этапа 1

Пользователь сделал выбор: [SELECTED_DECISIONS.json](SELECTED_DECISIONS.json). В частности, **объём первой статьи B** и **исходная онтология B** выбраны вместо рекомендаций A; разметка изменена на машинный ансамбль без текущей человеческой валидации. Рекомендации в таблицах ниже сохранены как история обсуждения и не отменяют выбранные решения.

Это рекомендации к обсуждению, не утверждённый протокол. В G1 утверждается вопрос, исходная онтология и структура дизайна. Окончательные операционные метрики, контрасты, границы существенности и размер корпуса фиксируются на G2 после development-пилота, до открытия закрытых данных. Смысл H0–H7 сохраняется при любом выборе.

## Приоритет и измеритель

| Решение | Вариант A | Вариант B | Рекомендация |
|---|---|---|---|
| Объём первой статьи | H1–H3 основные, H4 вторичная, H6 exploratory, H5–H7 отдельный модуль. Плюсы: сильный центральный вопрос, меньше зависимостей. Минус: прикладной результат может выйти позднее | Все H1–H7 одновременно. Плюс: полная программа. Минусы: больше бюджета, проверок, мощности и технических шлюзов | A |
| Исходная онтология | Восемь фиксированных ролей + ambiguous, data-driven кластеризация параллельно. Плюсы: проверяемая семантика и человеческая оценка. Минус: словарь может ограничивать наблюдаемый эффект | Сначала кластеры, затем роли. Плюс: больше свободы открытия. Минусы: сложнее сопоставление семей и риск навязанного выравнивания | A; менять роли только на development с новой revision |
| Единица группировки | Консервативный root: все варианты, переводы и близкие производные вместе. Плюс: меньше утечки. Минусы: меньше эффективная выборка, сложнее происхождение | Отдельные IDs задач без объединения производных. Плюс: проще реализация. Минус: создаёт риск утечки и псевдорепликации, непригоден при связанных вариантах | A; неизвестное происхождение в карантин |
| Проверка переноса | Обязательная новая семья × новые roots; знакомые задачи отдельный диагностический контраст. Плюс: сильнее обобщение. Минусы: сложнее splits, нужны достаточные страты | Новая семья на знакомых задачах. Плюсы: дешевле, изолирует модельную ось. Минус: вывод ограничен знакомыми задачами | A для центрального результата; B дополнительная диагностика |
| Сегментация | S1 человеческие смысловые границы + S2 предложения + S3 реальные token blocks. Плюс: проверка зависимости от измерителя. Минус: трудозатраты и токен-карты | Только S2. Плюс: быстро. Минус: не закрывает требование устойчивости и три сегментатора этапа 2 | A; S2 можно разрабатывать первой |
| Разметка E0 | Два человека независимо, затем adjudication, согласие до обсуждения. Плюс: оценка ошибки. Минус: трудозатраты | Один человек + повторная саморазметка. Плюс: дешевле. Минус: оценивает повторяемость одного человека и не заменяет независимое межэкспертное согласие | A; AdamCage может быть одним аннотатором, другой должен действовать независимо |
| Предварительные E0 targets | Оставить v0.1 как engineering-триаж; окончательные пороги отдельно зафиксировать до независимой валидации. Плюс: можно проверять дизайн сейчас. Минус: числа пока не обоснованы данными метода | Сначала дополнительная методическая development-разметка, затем предложить targets. Плюс: больше эмпирического основания. Минус: дольше, нужен контроль круговой приёмки | A с возможностью пересмотра на development; не снижать порог ради прохода увиденной валидации |

## Кандидаты первичных метрик

| Гипотеза | Вариант A | Вариант B | Рекомендация |
|---|---|---|---|
| H1 | Macro-F1 на отложенных семьях. Плюсы: понятный баланс ролей. Минус: высокий score может объясняться лексикой | Разница macro-F1 относительно TF-IDF baseline. Плюс: показывает добавочную ценность измерителя. Минус: зависит от силы baseline | B как контраст, A и recall по ролям обязательны для интерпретации |
| H2 | Сходство поддержанных рёбер при matched объёме. Плюс: непосредственно топология. Минусы: чувствительно к поддержке/порогу и плотности графа | Перенос прогноза следующего состояния против частотной/позиционной модели. Плюс: проверяет полезность структуры. Минус: прогноз сам по себе не устанавливает общую топологию | A для топологии, B обязательная дополнительная проверка; не принимать H2 только по B |
| H3 | Различие условных переходных распределений по общим состояниям. Плюс: прямой динамический контраст. Минусы: редкие переходы, нужен учёт ошибки меток | Различия длительностей ролей/возвратов. Плюс: проще объяснять. Минусы: зависят от длины и сегментации | A основная кандидатура, B вторичная; сравнивать по задачам и условиям исполнения |
| H4 | Сходство успешных против ошибочных траекторий внутри сопоставимых задач. Плюс: меньше task confounding. Минус: нужны смешанные исходы | Прогноз correctness по динамике. Плюс: практическая ясность. Минус: косвенно проверяет именно convergence | A для H4; B дополнительная прогнозная проверка |
| H5 | Изменение вероятности правильного завершения по повторным probes. Плюс: учитывает случайность. Минус: стоимость | Единственный ранний правильный probe при ошибочном финале. Плюс: дёшево. Минусы: случайность и множественный поиск префиксов | A; B лишь development-диагностика |
| H6 | Сопоставимая пара одной модельной линии. Плюс: меньше различий подготовки. Минусы: наблюдательный характер, нужен реальный допуск | Регрессия по размеру всей неоднородной когорты. Плюс: больше диапазон. Минусы: архитектура, обучение и provider смешиваются с размером | A при доступной паре; иначе оставить вопрос неразрешённым |
| H7 | Held-out прогноз correctness/полезности продолжения по доступному префиксу. Плюс: проверка без live cancellation. Минус: ещё не доказывает экономию | Реальная stopping policy при matched риске и полной стоимости. Плюс: прикладная проверка. Минусы: API-реализуемость и накладные расходы | A сначала, B для полной H7; A не заменяет её прикладную часть |
| H0 | Практическая эквивалентность остаточного эффекта при валидном измерителе. Плюс: содержательный отрицательный результат. Минусы: нужны заранее заданная малая область и точные интервалы | Отсутствие статистической значимости. Плюс: легко вычислить. Минус: не отличает малый эффект от недостатка информации | A; недостаточная точность и непригодный измеритель — отдельные исходы |

## Статистические поля §11.2 и provenance

| Поле/решение | Вариант A | Вариант B | Рекомендация |
|---|---|---|---|
| Направленность | H1/H2-прогноз/H7 — заранее положительное преимущество; H3/H6 — двусторонние различия, когда знак не задан. Плюс: соответствует вопросу. Минус: контраст нужно определить заранее | Все двусторонние. Плюс: проще единое правило. Минус: менее адресно проверяет направленные преимущества | A как кандидат G2; знак не выбирать после результата |
| Основной null | Частоты/позиция/длина/domain/task structure, каждый контроль с явными инвариантами. Плюс: сильнее конкурирующее объяснение. Минус: сложнее построение | Полная случайная перестановка сегментов. Плюс: простой sanity check. Минус: слишком лёгкий единственный контроль | A; B дополнительный |
| Величина эффекта | Разница в единицах выбранной метрики на одинаковых задачах/семьях. Плюс: интерпретируемость. Минус: разные метрики несопоставимы напрямую | Стандартизованный эффект. Плюс: безразмерная шкала. Минус: зависит от дисперсии и может скрывать практический размер | A основная, B при необходимости вторичная |
| Доверительный интервал | Парный bootstrap task roots, сохраняя модели/генерации/варианты вместе; внутренний resampling только при обоснованной схеме. Плюс: соответствует зависимости. Минусы: мало roots и нестабильные редкие роли | Иерархическая mixed-effects модель. Плюс: явная структура факторов. Минусы: предпосылки и сложность | A стартовая кандидатура, B robustness при проверенных предпосылках; семьи не объявлять выборкой всех архитектур |
| Значимость | Blocked permutation с допустимой exchangeability + интервалы эффектов. Плюс: близко к структуре дизайна. Минус: exchangeability нужно обосновать отдельно для контраста | Параметрические тесты/model-based inference. Плюс: потенциальная эффективность. Минус: чувствительность к предпосылкам | A для заранее подходящих контрастов, B при обосновании; универсального permutation test для всех H нет |
| Множественные проверки | Ограниченное confirmatory-семейство заранее выбранных контрастов H1–H3, кандидат Holm; exploratory отдельно, кандидат FDR. Плюс: понятная граница основных выводов. Минус: меньше гибкость | Все H1–H7 и множество вариантов в одной семье. Плюс: единый контроль. Минусы: ниже чувствительность и перегруженная программа | A, точный список/процедура фиксируются G2; разделение не делает exploratory confirmatory |
| Минимально существенный эффект | Выбрать по научной/практической полезности и измерительной ошибке; проверить достижимость мощности на development. Плюс: содержательная граница. Минус: нужен аргумент полезности | Взять наблюдённый пилотный эффект как минимальный. Плюс: просто. Минус: круговая цель и оптимизм | A; окончательное число пока отложено, порог не подгонять под проход пилота |
| Недостаточная мощность | Simulation-based размер выборки и допустимая ширина CI относительно существенного эффекта. Плюс: учитывает редкость смешанных исходов/ролей. Минусы: зависит от сценариев симуляции | Только фиксированное число трасс. Плюс: удобный бюджет. Минус: не гарантирует информативные задачи | A, бюджет является ограничением, а не доказательством мощности |
| DomainPack | Собственный `reasoning_universalis_v1` с RouterAI external evidence и отдельным measurement-кодом. Плюсы: provenance и честная идентичность исполнения. Минус: нужен адаптер/контрактные тесты | Переделать demo `risen_universalis_v1`. Плюс: короткий путь к демонстрации. Минус: нарушает разделение demo/science проекта | A |
| Идентичность модели | Явное условие model × provider × доступная revision/quantization; unknown сохраняется. Плюс: честные выводы. Минус: переносимость ограничена условиями исполнения | Считать API model ID точной идентичностью весов. Плюс: проще. Минус: необоснованная точность | A |
| G1 | AdamCage утверждает конкретный commit и manifest SHA-256 артефактов; статус pending до явного утверждения. Плюс: проверяемая приёмка. Минус: изменение утверждённых файлов требует новой записи | AdamCage утверждает только устное описание без hashes. Плюс: быстро. Минус: не закрывает критерий G1 | A; имя уже назначено, утверждение версии ещё предстоит |

Обоснование статистической осторожности: [ASA statement](https://www.amstat.org/asa/files/pdfs/p-valuestatement.pdf) различает p-value и величину эффекта; [Saravanan et al.](https://arxiv.org/abs/2007.07797) обсуждают учёт вложенной структуры bootstrap. Перенос этих методов в наш дизайн — предлагаемое решение с отдельной проверкой предпосылок, а не доказанная пригодность.
